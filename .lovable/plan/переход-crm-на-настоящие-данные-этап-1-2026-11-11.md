# Переход CRM на настоящие данные — этап 1

## Что решили
- База данных PostgreSQL на вашем сервере 84.201.173.244, данные хранятся в РФ.
- Серверная часть лежит в папке `server/` этого же репозитория и работает на адресе https://api.aquariuswash.ru.
- Аккаунтов два: **Администратор** (интерфейс мойщика) и **Владелец** (всё плюс дашборд, финансы, мойщики, уведомления). Мойщиков Рому, Малика и Сергея по-прежнему выбирают в заказе.
- Начинаем с пустой базы. Прайс-лист переносим как есть: он актуальный.

## Этап 1 (сейчас): вход, запись, расписание
1. Настоящий вход в CRM по логину и паролю. Пароли храним в зашифрованном виде, сессия живёт 30 дней. Мок-вход убираем.
2. Запись с сайта (окно записи и калькулятор) попадает в базу, и свободное время берётся из реальных записей.
3. Расписание CRM (день/неделя, компьютер и телефон) читает и меняет настоящие записи: создание, подтверждение, отмена, начало мойки, «Машина готова», оплата, бокс, мойщик.
4. Прайс-лист хранится в базе, его редактирует владелец, сайт показывает цены оттуда.
5. Остальные страницы (клиенты, лояльность, финансы, дашборд, уведомления) пока на демо-данных, их переводим следующими этапами.

## Что сделаете вы на сервере (дам команды)
- Установить PostgreSQL, создать базу и пользователя.
- Запустить сервис API и добавить в Caddy адрес api.aquariuswash.ru.
- Задать пароли двух аккаунтов одной командой (в код пароли не попадают).
- Включить ежедневный бэкап базы.

## Следующие этапы
2. Клиенты и история визитов. 3. Финансы, мойщики и дашборд. 4. Лояльность и бонусы (вход клиентов по SMS — нужен SMS-сервис). 5. Уведомления и PWA.

## Технические детали
- `server/`: Node 22 + Hono, Drizzle ORM + PostgreSQL, миграции в `server/migrations`, отдельный `package.json`, systemd-сервис на 127.0.0.1:4000.
- Авторизация: argon2 + httpOnly cookie на домене `.aquariuswash.ru`, роли `owner` и `admin` хранятся на сервере, права проверяет каждый endpoint.
- Публичные endpoints: `GET /v1/prices`, `GET /v1/slots`, `POST /v1/bookings` (с ограничением частоты запросов). Для CRM: `/v1/auth/*`, `/v1/crm/bookings`, `/v1/crm/prices`.
- Во фронтенде мок-хранилище в `src/lib/crm/` заменяем клиентом API: экраны не переписываем.
- В превью Lovable сервера API нет, поэтому проверяем на вашем сервере или локально.
